Validate against reality, then let the model retry

@agent.output_validator
async def check_sql(ctx: RunContext[Conn], out: Sql) -> Sql:
    if ctx.partial_output:  # streaming snapshot
        return out
    try:
        await ctx.deps.execute(f'EXPLAIN {out.query}')
    except QueryError as e:
        raise ModelRetry(f'Invalid query: {e}')
    return out

# output function: the model must call it to finish
def run_sql(ctx: RunContext, query: str) -> list[str]:
    if not query.upper().startswith('SELECT'):
        raise ModelRetry('Only SELECT is allowed.')
    return db_rows(query)
sql = Agent('openai:gpt-6.1-sol', output_type=run_sql)

  • ModelRetry sends your message back to the model, which tries again.
  • Output retries use the output budget (default 1): set retries={'output': 3}.
  • validation_context feeds Pydantic validators (info.context) and never reaches the model.
  • When streaming, validators run on every partial: guard side effects with ctx.partial_output.

Pydantic AI Field Guide · Core agent · docs/output.md#output-validator-functions

Pydantic already validates the shape of the output; output validators let you validate against the real world, for example by running EXPLAIN on generated SQL, checking that a URL resolves, or confirming an ID exists. Return the output (optionally modified) or raise ModelRetry with a message the model can act on. The retry shows up in history as a retry feedback part, and costs one unit of the output retry budget, which defaults to 1. Output functions go one step further: the function itself is the output type, so the model has to call it with valid arguments to finish the run, and its return value becomes result.output. TextOutput(fn) is the plain-text version. Real-world ideas: text-to-SQL over analytics with a read-only role, generate-then-validate for any DSL (regex, cron expressions, config files), or a router agent whose output functions hand off to specialist agents.
