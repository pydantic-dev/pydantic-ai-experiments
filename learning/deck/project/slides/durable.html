Pydantic AI Field Guide · Durable execution · docs/durable_execution/*.md

A durable engine journals each model request and wrapped tool call as a unit, replays completed units after a crash and retries the one that was in flight. In version 2 you attach exactly one durability capability to a normal Agent; the old TemporalAgent, DBOSAgent and PrefectAgent wrappers are deprecated. The key trap: the run is durable only when agent.run() executes inside the engine’s workflow or flow. When migrating from DBOSAgent or PrefectAgent you must add @DBOS.workflow or @flow yourself, or the run is silently not durable. Temporal is the most powerful and the strictest: workflow code must be deterministic, deps must be serializable, payloads are capped at 2 MB, and agent name and toolset id must be stable. Set activity_config, because Temporal’s default is unlimited retries. DBOS is the simplest to try locally, with sqlite:///x.sqlite as the system database. Tools should be idempotent because in-flight steps re-run on replay, and changing durable units breaks in-flight replays, so drain or version before deploys. The Harness adds more engines: AWSLambdaDurability, PGTaskDurability, AbsurdDurability and AzureDurableTaskDurability. Durability is not storage: for ordinary chats, a Conversation in a jsonb column is enough. Exercise: run DBOS on SQLite with a slow step tool, kill the process mid-run, restart and confirm the model call isn’t re-billed.
