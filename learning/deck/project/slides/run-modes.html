Five ways to run the same agent

MethodYou getReach for it when
run_sync()AgentRunResultScripts and quick experiments (in Jupyter, use await agent.run)
await run()AgentRunResultAsync servers such as FastAPI handlers
run_stream()StreamedRunResultStreaming text or partial structured output to a UI
run_stream_events()Event stream, then AgentRunResultEventYou need every event, including tool calls and results
iter()AgentRun, node by nodeCustom logic between steps, or editing a node before it runs

Gotcha: run_stream stops early

The first output matching output_type is final; tool calls after streamed text are not executed. Use run_stream_events or iter when tools must run.

Per-run overrides

Every method accepts model, output_type, instructions, capabilities, retries, timeout, cancellation_token, conversation and metadata.

Pydantic AI Field Guide · Core agent · docs/agent.md#running-agents

All five methods drive the same graph loop; they differ in how much of it you see. run_sync is a blocking wrapper around run. run_stream is a context manager whose StreamedRunResult offers stream_text, stream_output (partially validated snapshots), get_output and cancel. Its big gotcha: it treats the first output that matches the output type as final, so tool calls that come after streamed text are not executed. run_stream_events yields PartStartEvent, PartDeltaEvent, FunctionToolCallEvent, FunctionToolResultEvent and FinalResultEvent, and ends with AgentRunResultEvent carrying the result. iter gives you an AgentRun you can async-iterate; use Agent.is_model_request_node and is_call_tools_node to branch, or drive it manually with await run.next(node). You can also emit your own CustomEvent dataclasses from tools with await ctx.emit(...) and listen with @agent.on_event. Experiment: send one prompt through all five and log what each shows you.
