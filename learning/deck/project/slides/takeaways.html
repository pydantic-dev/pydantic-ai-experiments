Takeaways

Eight things to remember

  • Agent[Deps, Output] is a typed container; a run is a loop; ctx is your handle.
  • The output type is the contract: validate, then ModelRetry.
  • Everything is a toolset; prefix early, approval is not authorization.
  • Capabilities are middleware: most v1 kwargs live there now.
  • One string picks the model; settings stack model < agent < run.
  • Climb the ladder slowly: agent, delegation, hand-off, graph, durable.
  • Everything is OpenTelemetry: evals grade answers and trajectories.
  • Learn offline with 'test', TestModel and FunctionModel.

Pydantic AI Field Guide · Research notes: six knowledge files in the session scratchpad

To recap the whole deck in eight lines: an Agent is a reusable typed container and every run is a graph loop driven through RunContext; the output type decides when a run ends, so validate it against reality and let the model retry; tools, MCP servers and frontend tools are all toolsets that compose with wrappers, and an approval is a UX step, not an authorization check; capabilities are version 2’s middleware and replaced most v1 keyword arguments; a single 'provider:model' string chooses the model class, provider and profile, and settings merge from model to agent to capability to run; move up the multi-agent ladder only as far as you need; everything emits OpenTelemetry, which powers Logfire, trajectory evals and online evals; and the cheapest way to learn all of it is offline with TestModel and FunctionModel.
