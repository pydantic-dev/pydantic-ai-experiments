Grade the trajectory, not just the answer

logfire.configure(send_to_logfire='if-token-present')
logfire.instrument_pydantic_ai()  # spans to grade
evaluators = [
    ToolCorrectness(expected_tools=['search', 'rerank'],
                allow_extra=True),
    TrajectoryMatch(expected_trajectory=['search', 'rerank'],
                order='in_order'),
    MaxToolCalls(max_calls=5),
]
# online: score production traffic in the background
agent = Agent('openai:gpt-6.1-sol', name='support',
    capabilities=[OnlineEvaluation(evaluators=[
        not_empty,  # every run
        OnlineEvaluator(evaluator=LLMJudge(rubric='Polite'),
                    sample_rate=0.05)])])  # 5% of runs

  • Trajectory evaluators check which tools ran, in what order, with what args; no LLM calls.
  • HasMatchingSpan asserts things like “delete_* was never called”.
  • Span names are invoke_agent X and execute_tool Y.
  • Online results are OTel gen_ai.evaluation.result events.

Pydantic AI Field Guide · Evals · docs/evals/evaluators/agentic.md, span-based.md, online-evaluation.md

Final answers can be right for the wrong reasons. Span-based evaluation grades the process using the OpenTelemetry spans captured while the task ran. HasMatchingSpan takes a SpanQuery that can match names, attributes, status and duration, combine conditions with not_, and_ and or_, and walk the tree with child_has, descendant_has and ancestor_has. To assert something never happened, root the query on a span and use no_descendant_has, because a top-level not_ passes if any single span fails the condition. The agentic evaluators are deterministic: ToolCorrectness compares the multiset of tools called, TrajectoryMatch scores call order as an F1 (exact, in_order or any_order), ArgumentCorrectness checks arguments, and MaxToolCalls and MaxModelRequests enforce budgets. Only local tools count, and sub-agent calls do count. Online evaluation reuses the same evaluators on live runs, through the OnlineEvaluation capability or the @evaluate decorator, with per-evaluator sample rates and concurrency; results are dispatched after the run completes and show up in Logfire as Live Evaluations. Under durable engines, pass OnlineEvaluation(id='...').
