Pydantic AI Field Guide · Observability · docs/logfire.md, docs/troubleshooting.md

Pydantic AI emits OpenTelemetry GenAI semantic-convention traces: one trace per run, with spans for each model request and tool call, plus metrics such as gen_ai.client.token.usage, operation.cost, time to first chunk, and prompt-cache health (pydantic_ai.cache.hit_ratio and collapse reasons). Logfire is the first-class viewer, and send_to_logfire='if-token-present' means nothing leaves your machine without a token; any OTel backend works with Agent.instrument_all() and your own TracerProvider and exporter. instrument_httpx(capture_all=True) shows the raw provider requests, which is the fastest way to answer “what exactly did the model receive?”. InstrumentationSettings controls privacy: include_content=False, include_binary_content=False, and the semantic-convention version. Setup helper: uvx logfire-cli wizard --task pydantic-ai; note that the .logfire directory it writes is gitignored but not excluded from Docker build contexts. The troubleshooting doc recommends the three-step loop on the right. Common errors it covers: event-loop problems in Jupyter (use await agent.run), the default request_limit of 50, exceeded max retries (improve docstrings or raise budgets) and unprocessed tool calls (resume with no prompt or repair_messages).
