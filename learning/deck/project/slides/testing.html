Test your code offline; use evals for answer quality

from pydantic_ai.models.test import TestModel
from pydantic_ai.models.function import AgentInfo, FunctionModel

models.ALLOW_MODEL_REQUESTS = False  # block real calls
agent = Agent('openai:gpt-6.1-sol', defer_model_check=True)

def scripted(messages, info: AgentInfo) -> ModelResponse:
    names = [t.name for t in info.function_tools]
    return ModelResponse(parts=[TextPart(f'tools={names}')])

def test_agent():
    tm = TestModel(custom_output_text='Sunny')
    with agent.override(model=tm):
        assert agent.run_sync('Weather?').output == 'Sunny'
    with agent.override(model=FunctionModel(scripted)):
        assert agent.run_sync('Hi').output == 'tools=[]'

  • TestModel calls every tool, then returns schema-valid output.
  • FunctionModel scripts exact responses, tool calls included.
  • override() swaps model and deps without touching app code.
  • Inspect last_model_request_parameters to see the tool schemas you generated.

Pydantic AI Field Guide · Core agent · docs/testing.md

Unit tests should check your code, not the model. Set models.ALLOW_MODEL_REQUESTS = False in your test setup so nothing accidentally calls a real provider, and build agents with defer_model_check=True so tests need no API key. TestModel takes custom_output_text, custom_output_args and call_tools to shape what it does. FunctionModel(fn) gets the message list and an AgentInfo (including function_tools and model settings) and returns any ModelResponse you like, so you can script a text-plus-tool-call response and check how your agent handles it. Combine capture_run_messages() with dirty_equals to assert on the exact messages. Limitations: TestModel ignores regex pattern constraints and cannot emulate native provider tools, so use override(native_tools=[]). For answer quality, use Pydantic Evals (section 6). Learning tip: these two models are the cheapest way to explore every feature in this deck.
