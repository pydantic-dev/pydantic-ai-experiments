A sandboxed coding agent in a few lines

agent = Agent('anthropic:claude-opus-5-5', capabilities=[
    DockerContainer(image='python:3.13-slim',
                allow_internet_access=False),
    Coder(),
])
result = agent.run_sync('Print the first 10 primes; run it.')
ref = result.workspace.ref  # persist it
later = agent.run_sync('Now the first 100.', workspace=ref)
await DockerContainer().destroy(ref)  # runs never do

# zero code: a terminal coding agent
# uvx --with "pydantic-ai-harness[coder]" clai \
#   -a pydantic_ai_harness.coder:coder_agent

  • Coder = FileSystem + Shell + RepoContext + self-delegation + context control.
  • Swap DockerContainer for Modal, E2B or Kubernetes in one line.
  • LocalWorkspace is not a sandbox: it runs with your permissions.
  • Never pass os.environ as env: it leaks API keys.

Workspaces are the hinge of the Harness: ctx.workspace gives tools somewhere to run commands and edit files, and the same agent code works on a local directory or a cloud sandbox. Sandboxes are created on first use, outlive the run (cloud ones keep billing), continue via message history, and can be reattached with result.workspace.ref passed as workspace=ref. Nothing destroys them for you, and a failed run gives no ref, so clean up in a Hooks on.run_error hook. Coder bundles FileSystem (read, write, edit, grep with root containment), a persistent shell, RepoContext (loads AGENTS.md and CLAUDE.md), SubAgents(include_self=True), ClearToolResults compaction, RepairToolArguments and caching. Install the [coder] extra for json-repair and ripgrep. Bind Coder on the Agent, not on run(). autonomy='low' to 'max' is prompt guidance, not enforcement; use Permissions for that. Commands get only PATH, HOME, LANG and LC_* unless you pass env= explicitly. Docker shares the host kernel and its default network can reach your LAN; microVM sandboxes (SmolSandbox, BoxLite) or cloud VMs isolate more.
