03 · Tools & capabilities

MCP: plug in any tool server, or become one

server = FastMCP('math')

@server.tool()
async def add(a: int, b: int) -> int:
    return a + b

agent = Agent('anthropic:claude-sonnet-5-5', toolsets=[
    MCPToolset(server, id='math'),  # in-process
    MCPToolset('http://localhost:8000/mcp'),
    MCPToolset(StdioTransport(command='python',
        args=['mcp_server.py'])).prefixed('local'),
])

# recommended shortcut: a capability
docs = MCP('https://mcp.example.com/api', id='docs')

  • MCP(url) capability: local by default, native=True for provider-side MCP.
  • MCPToolset (FastMCP-based) for lifecycle control; async with agent keeps connections open.
  • Sampling & elicitation: servers can use your LLM or ask the user.
  • MCPSamplingModel runs an agent inside an MCP tool, no server keys needed.

v2 removed MCPServerStdio / SSE / StreamableHTTP.

MCP shows up three ways. MCPToolset is the client toolset, built on FastMCP; its first argument can be a URL (Streamable HTTP, or SSE if the path ends in /sse), a .py or .js script run over stdio, a FastMCP transport or Client, or an in-process FastMCP server, which is perfect for testing with no network. Useful options: id, tool_error_behavior ('retry', 'failed' or 'error'), cache_tools, sampling_model, elicitation_handler, auth (a function of ctx for per-user credentials). load_mcp_toolsets('mcp_config.json') reads Claude-Desktop-style config files, but those can spawn arbitrary commands, so only use files you trust. MCPServerTool is the provider-native version. The MCP capability chooses between them and, unlike MCPToolset, includes server instructions, which carry operator authority. To expose an agent as an MCP server, put it inside a FastMCP tool and run it with MCPSamplingModel(session=ctx.session), so its LLM calls go back through the client. Gotcha: FastMCP 4 defaults to a protocol that forbids mid-tool-call sampling and elicitation (NoBackChannelError); use FastMCP 3 or Client(..., mode='legacy').
