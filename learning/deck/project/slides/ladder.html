05 · Multi-agent

Climb the complexity ladder only as far as you need

1

Single agent

One model, tools and a typed output. Most apps stop here.

2

Delegation

A tool awaits a child agent and returns its output; budgets are shared.

3

Programmatic hand-off

Your code, or a human, decides which agent runs next.

4

Graphs

Typed state machines or parallel dataflow built with GraphBuilder.

5

Durable & deep agents

Engines survive crashes and long waits; Harness adds planning, sub-agents and sandboxes.

Pydantic AI Field Guide · Multi-agent · docs/multi-agent-applications.md

This ladder comes straight from docs/multi-agent-applications.md, which warns against reaching for graphs too early: “don’t use a nail gun unless you need a nail gun”. A single agent with good tools and a typed output solves a surprising amount. Delegation is the next step: a tool calls another agent, perhaps a cheaper model with a different output type or a clean context, and control returns to the parent. Programmatic hand-off is plain Python: run one agent, inspect its typed output, and decide what runs next, possibly after asking a human. Graphs give you an explicit, diagrammable state machine and real parallelism with map and join. At the top, durable execution engines (Temporal, DBOS, Prefect, Restate, Airflow) keep runs alive across crashes and multi-day waits, and Harness capabilities such as SubAgents, Planning and sandboxes build “deep agents”. Evals and Logfire are the development loop around every rung.
