03 · Tools & capabilities

Everything is a toolset, and toolsets compose

weather = FunctionToolset([temp_c, temp_f])
clock = FunctionToolset([now])

toolset = (
    CombinedToolset([weather.prefixed('weather'),
                     clock.prefixed('clock')])
    .filtered(lambda ctx, td: 'temp_f' not in td.name)
    .renamed({'current_time': 'clock_now'})  # new: old
    .approval_required(
        lambda ctx, td, args: td.name.startswith('weather'))
)
agent = Agent('test', toolsets=[toolset],
              output_type=[str, DeferredToolRequests])

  • @agent.tool functions, MCP servers and frontend tools are all toolsets, merged per run.
  • WrapperToolset: subclass to log, cache or redact one toolset.
  • ExternalToolset: tools the browser or another service executes.
  • @agent.toolset: build tools per run, e.g. a per-user MCP server.
  • Duplicate names raise errors: prefix early.

Pydantic AI Field Guide · Tools · docs/toolsets.md

A toolset is any collection of tools behind get_tools and call_tool. Your decorated functions live in an internal FunctionToolset, an MCP server is an MCPToolset, and frontend tools are an ExternalToolset. Fluent wrappers compose them: prefixed, filtered, renamed (which maps new name to old name), prepared (rewrite definitions per step, but not add or rename), approval_required, defer_loading, include_return_schemas and with_metadata. Toolsets can be supplied on the Agent, on a run (added), with @agent.toolset for dynamic per-run construction, or with agent.override(toolsets=) in tests (replaces all). FunctionToolset accepts instructions that are appended after the agent’s. ExternalToolset calls end the run as DeferredToolRequests.calls so a browser or another service can execute them; the AG-UI and Vercel AI adapters use it for frontend tools. For a custom registry, subclass AbstractToolset. If you also need hooks or settings, write a capability instead. Note that in version 2, FunctionToolset.tool requires a RunContext first parameter.
