Pydantic AI Field Guide · Models · docs/models/overview.md, docs/gateway.md

Three building blocks sit behind every model string. A Model class speaks one wire API (OpenAIResponsesModel, OpenAIChatModel, AnthropicModel, GoogleModel and so on). A Provider handles auth, base URL and the HTTP client. A Profile describes how to shape requests for that model family: schema rules, strict tools, structured-output support, context window and supported native tools. 'provider:model' builds all three; instantiate classes yourself only to override the provider (custom key, proxy, region) or the profile. Install the matching extra, e.g. pydantic-ai-slim[anthropic]. The Pydantic AI Gateway, managed through Logfire, gives one key for OpenAI, Anthropic, Google, Groq and Bedrock, with spend caps and failover endpoints: Agent('gateway/openai:gpt-6.1-sol'). Model names in the docs such as {{ openai:medium }} are docs-only aliases, not runtime syntax. KnownModelName is a Literal for autocomplete only. Separately, decision models (typesafe:, system-one: including local Ollama, openai-decisions:, google-decisions:) answer typed questions with probabilities and are a cheap way to classify.
