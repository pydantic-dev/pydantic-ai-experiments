Delegation: an agent inside a tool

selector = Agent('openai:gpt-6.1-sol', name='selector',
    instructions='Use jokes, then return the best one.')
generator = Agent('google:gemini-3.8-flash',
    name='generator', output_type=list[str])

@selector.tool
async def jokes(ctx: RunContext, count: int) -> list[str]:
    r = await generator.run(f'Write {count} jokes.',
                            usage=ctx.usage)  # shared budget
    return r.output

result = selector.run_sync('Tell me a joke.',
    usage_limits=UsageLimits(request_limit=5))
print(result.usage)  # covers both agents

  • Delegating tools must be async: run_sync inside a tool raises.
  • Always set name=: it labels spans and durable activities.
  • Hand-off instead: run agents in sequence and branch on typed output.
  • Output-function hand-off: a router whose output_type calls the next agent.

Agent delegation: the parent’s tool awaits child.run(...) and returns its output. Pass usage=ctx.usage so the child’s tokens and requests roll into the parent’s totals and its UsageLimits; a sub-agent that shares usage should also get usage_limits=ctx.usage_limits. Pass deps=ctx.deps if the child needs them; the child’s deps must match or be a subset of the parent’s. Agents are stateless globals, so don’t put them in deps. Under Temporal, tools get a copy of RunContext, so delegate usage is lost unless you return it. A shared CancellationToken cancels the whole tree. Programmatic hand-off: share a RunUsage() across sequential runs and pass message_history= when context should carry over; flight_booking does exactly this, including a human confirmation step. Output-function hand-off: put an async function such as hand_off_to_sql_agent in the router’s output_type; inside it, run the next agent with message_history=ctx.messages[:-1]. The router never regains control. Harness shortcut: SubAgents gives the model one delegate_task tool with per-delegate budgets. Exercise: medical_agent_delegation doesn’t pass usage=ctx.usage; add it.
