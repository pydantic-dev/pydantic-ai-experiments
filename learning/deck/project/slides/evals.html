Pydantic AI Field Guide · Evals · docs/evals.md, docs/evals/*

pydantic_evals is a separate package (no dependency on pydantic-ai) for evaluating any stochastic function. A Dataset holds Cases (inputs, optional expected_output, metadata, per-case evaluators) plus dataset-wide evaluators and report evaluators. evaluate or evaluate_sync runs your task over the cases, with max_concurrency, repeat to measure variance, task_timeout and retry options, and returns an EvaluationReport; report.print(baseline=old_report) shows an A/B diff. Evaluators return a bool (assertion), a number (score), a string (label), an EvaluationReason, or a dict of these. Custom evaluators are @dataclass subclasses of Evaluator with an evaluate(ctx) method, and in version 2 a plain function works too. LLMJudge produces a pass assertion with a reason, and can add a 0 to 1 score; its default model is still hard-coded to openai:gpt-5.2, so pass model= or call set_default_judge_model. GEval returns raw integer scores. dataset.to_file('cases.yaml') writes a JSON schema for editor autocomplete, and generate_dataset can have an LLM draft typed cases. Gotcha found in research: the docs say the judge only runs if basic checks pass, but all case evaluators actually run concurrently. Study examples/pydantic_ai_examples/evals, scripts 03, 02, 04, then 01.
