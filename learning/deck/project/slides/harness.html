Pydantic AI Field Guide · Harness · docs/harness/index.md

The Harness is a separate package (pip install pydantic-ai-harness, import pydantic_ai_harness) in the same monorepo, versioned 0.X in lockstep with pydantic-ai 2.X and pinning the exact matching pydantic-ai-slim. “Harness” means everything around the model: the loop, tools and context management. Core stays lean and keeps what needs framework or provider support (Thinking, WebSearch, MCP, native compaction, ToolSearch, Caching, LocalWorkspace); the Harness adds what long-running, file-touching, unattended agents need. Most capabilities have their own extra, e.g. [coder], [modal], [codemode], [skills], [github]. File and shell capabilities need a workspace: LocalWorkspace('.') from core (not a sandbox) or a sandbox capability. List order matters, for example compaction before Memory, and HandleDeferredToolCalls after Permissions. Other notable entries: CodeMode (tools become one run_code tool executed in the Monty sandbox), CapabilityCreation (the agent writes its own capabilities), ExaSearch, PlaywrightBrowser, BrowserUse, ACP for editors, and GitHub Agentic Workflows. 0.x means APIs still change between minors; read the Upgrading sections.
