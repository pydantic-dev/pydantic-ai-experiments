Graphs: typed state machines and parallel dataflow

summarizer = Agent('openai:gpt-6.1-sol',
    instructions='Summarize in one sentence.')
g = GraphBuilder(input_type=list[str], output_type=list[str])

@g.step
async def summarize(ctx: StepContext[None, None, str]) -> str:
    return (await summarizer.run(ctx.inputs)).output

collect = g.join(reduce_list_append, initial_factory=list[str])
g.add(g.edge_from(g.start_node).map().to(summarize),  # fan out
      g.edge_from(summarize).to(collect),  # fan in
      g.edge_from(collect).to(g.end_node))
graph = g.build()
out = await graph.run(inputs=['doc 1', 'doc 2'])
print(graph)  # Mermaid diagram

  • Steps: functions with explicit edges, map, broadcast, joins and decisions.
  • BaseNode classes: edges come from return annotations.
  • Both mix in one GraphBuilder.
  • v2 removed graph persistence.

Pydantic AI Field Guide · Graphs · docs/graph.md, docs/graph/builder/*.md

pydantic-graph is a type-hint-driven async graph library with no dependency on pydantic-ai, although it powers the agent loop itself. In version 2 every graph is assembled with GraphBuilder. Two styles mix freely. BaseNode style: a node is a dataclass subclass of BaseNode[State, Deps, RunEnd] whose async run(ctx) returns the next node or End(value), and the return annotation defines the outgoing edges; register them with g.add_reachable. Step style: @g.step functions receive ctx.inputs from the previous step; edges are explicit with g.edge_from(a).to(b); .map() fans out one task per item; g.join(reducer, initial_factory=...) fans in with reducers such as reduce_list_append, reduce_dict_update, reduce_sum or ReduceFirstValue (for races); g.decision().branch(g.match(T).to(step)) branches. graph.run(state=, deps=, inputs=) returns the raw output; graph.iter() lets you step through tasks; print(graph) or graph.render() gives a Mermaid diagram. Gotchas: joins reduce in completion order, not input order (carry an index if order matters), and parallel tasks share one mutable state. Persistence was removed in v2: use Harness StepPersistence for agent checkpoints, Conversation for chats, or a durable engine. Ideas: write-critique-rewrite loops, document map-reduce, model races.
